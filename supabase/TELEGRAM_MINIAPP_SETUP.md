# Telegram Mini App — безопасный вход LOOPA

Режим мини-приложения открывается через https://t.me/LOOPAvideo_bot/loopa.

## Что делает интеграция

- При первом запуске новый пользователь может явно зарегистрироваться через Telegram. Для сохранения существующего профиля пользователь сначала открывает его прежним способом входа, затем нажимает «Привязать Mini App».
- Следующие запуски: Mini App отправляет `Telegram.WebApp.initData` на Supabase Edge Function, которая проверяет HMAC с токеном **бота LOOPAvideo_bot** и срок данных (10 минут). При известной привязке сервер выдаёт одноразовый hash для получения Supabase-сессии.
- Таблица связывает Telegram user ID и **существующий** Supabase user UUID. Ничего не объединяется по имени/телефону, не создаются новые аккаунты автоматически. Друзья, сообщения, комнаты сохраняются на прежнем UUID.
- Если у аккаунта не было email, **при явной привязке** сервер добавляет технический адрес `miniapp-link-<uuid>@auth.loopacinema.invalid` для поддержки Supabase magiclink. На этот адрес письма не доставляются, это не почта пользователя. Внешний интерфейс его скрывает.

## Сохранение гостевого профиля

Если пользователь уже смотрит как гость, нужно войти именно в этот профиль и привязать Telegram через «Профиль → Конфиденциальность → Привязанные аккаунты» или кнопку Mini App. Привязка сохраняет исходный UUID и доступ к друзьям, комнатам и точкам просмотра. Не выбирай регистрацию для другого аккаунта: два существующих профиля автоматически не объединяются.

Настройка облачных точек просмотра, Google-привязки и ограничений домена описана в `supabase/ACCOUNT_CONTINUITY_SETUP.md`.

## Порядок развёртывания

1. В тестовой среде примени миграции `20261108_telegram_miniapp_links.sql`, `20261119162157_telegram_single_use_login.sql`, `20261119162733_telegram_action_budgets.sql` и `20261119163115_telegram_pending_link.sql`. После проверки и согласования примени миграции к production перед обновлением Edge Function.
2. В Supabase Edge Functions добавь секрет `TELEGRAM_BOT_TOKEN` — токен **этого же бота LOOPAvideo_bot** из BotFather. **Никогда не вставляй секрет в index.html или публичный GitHub**, не присылай его в чат.
3. Проверь доступность `SUPABASE_URL` и одного из `SUPABASE_SERVICE_ROLE_KEY` / `SUPABASE_SECRET_KEY` / `SUPABASE_SECRET_KEYS.default` в окружении Edge Functions. Значение сервисного ключа нельзя публиковать.
4. Разверни функцию `telegram-miniapp-auth` по `supabase/functions/telegram-miniapp-auth/index.js` с конфигурацией из `supabase/config.toml` (для первого входа `verify_jwt=false`, проверки происходят внутри функции). Через Supabase CLI: `supabase functions deploy telegram-miniapp-auth --project-ref <REF> --no-verify-jwt`.
5. Опубликуй совместимую версию сайта после миграций и Edge Function. Слияние в `main` запускает GitHub Pages.
6. Для существующего профиля выполни проверку ниже перед переключением способов входа.

Вместо `--no-verify-jwt` можно использовать настройки из `supabase/config.toml` при локально настроенном Supabase CLI. **Не включай публичный доступ к другим функциям.**

### Проверка существующего профиля перед переключением входа

1. В закрытом рабочем журнале зафиксируй UUID существующего профиля, наличие Telegram-привязки и сводку данных. Сохрани копии данных и файла аватара, проверь восстановление на изолированном стенде.
2. В действующей сессии профиля открой Mini App с нужного Telegram. Проверка состояния должна вернуть `linked`. При `claimed_by_another_profile` или `profile_linked_elsewhere` останови переключение и согласуй восстановление доступа. При `unlinked` сначала подтверди контроль над исходным профилем и Telegram, затем выполни явную привязку.
3. Открой приложение в другом тестовом сеансе Telegram с тем же аккаунтом Telegram, где у LOOPA ещё нет веб-сессии. Проверь, что подтверждённый вход возвращает исходный UUID, а имя, аватар, комнаты, история и настройки доступны. Повтори на iOS и Android. Храни идентификаторы и результаты в закрытом журнале.
4. До успешного прогона сохрани прежний вход владельца. Публичное переключение способов входа и удаление старых профилей проводятся отдельными изменениями. При сбое восстанови доступ прежним способом, сохранив исходный UUID и действующие привязки.

### Лимиты Telegram

У каждого подтверждённого Telegram ID свой бюджет на каждое действие. Вход допускает 6 запросов сразу с восстановлением 1 запроса за 10 секунд. Регистрация и привязка допускают по 3 запроса с восстановлением 1 за минуту. Проверка статуса допускает 12 запросов с восстановлением 1 за 5 секунд. При исчерпании бюджета функция отвечает 429 с `Retry-After`. При ошибке проверки бюджета клиент получает 503.

### Повтор привязки после сбоя

Привязка сначала резервирует пару Telegram ID и UUID профиля. При сбое повтори привязку из того же профиля. Функция перечитает состояние Auth и завершит операцию. Незавершённая привязка не выдаёт токен входа. У резерва нет автоматического срока истечения, поскольку изменение email в Auth могло завершиться при потере ответа. После удаления профиля из Auth резерв удаляется по внешнему ключу. Синтетический email для существующего профиля привязан к его UUID и может заполнить только пустое поле email. Для новой регистрации функция сохраняет серверную отметку в Auth и восстанавливает тот же UUID при потере ответа. Начатая регистрация и привязка к существующему профилю взаимно исключаются для одного Telegram ID. Серверная отметка завершённой регистрации не восстанавливает удалённую связь. Регистрация прежних версий без этой отметки требует ручной сверки, если осталась без завершённой привязки.

### Откат

Для отката привязки сохрани служебные таблицы и триггеры. Согласуй переход на предыдущую Edge Function после проверки незавершённых резервов. Старая функция может менять внутренний email до сохранения привязки. Для отката лимитов разверни версию Edge Function с одноразовым обменом и сохрани служебные таблицы. Если требуется откат и одноразового обмена, сохрани таблицу отметок. Предыдущая версия снова допускает повторную выдачу токена, поэтому согласуй такой откат отдельно. После нового запуска Mini App требуется свежее подписанное подтверждение Telegram, если предыдущий обмен уже был зарезервирован. Обычный вход через email и другие настроенные способы остаётся доступен.

## Важные проверки перед запуском для всех пользователей

- Проверить SQL RLS: у `anon` и `authenticated` нет доступа к `telegram_miniapp_links`.
- Проверить подпись: изменённое / истёкшее `initData` отвергается сервером. Проверить, что повторный обмен уже использованного подтверждения просит заново открыть Mini App, а новая сессия запуска позволяет войти.
- Проверить попытку связать чужой профиль / второй Telegram — должна возвращаться ошибка 409.
- Проверить авторизацию с настоящего iPhone внутри Telegram; до реального теста нельзя считать интеграцию готовой.
- После деплоя проверь CORS: `https://loopacinema.ru` — единственный разрешённый источник.

Для этой правки достаточно обычной публикации сайта через GitHub Pages и обновления функции `telegram-miniapp-auth`. Конфигурация Cloudflare Worker `loopa-telegram-auth` остаётся прежней.
